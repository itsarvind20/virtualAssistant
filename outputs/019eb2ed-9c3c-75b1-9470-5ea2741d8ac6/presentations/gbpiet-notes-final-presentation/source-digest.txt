- 7.1 Authentication Module [Heading 2]
- The authentication module is responsible for providing secure access control to the application and ensuring that only authorized users can access protected features. It supports email/password registration, login, Google authentication, profile completion, logout functionality, and current-user session restoration. The module acts as the entry point to the system and is designed to provide both security and user convenience. [Heading 2]
- Passwords are never stored in plain text. Instead, they are securely hashed using the bcrypt library before being stored in the database. During login, entered credentials are verified against the stored hashed password. After successful authentication, JWT access and refresh tokens are generated and stored in HTTP-only cookies. This approach improves security by preventing client-side scripts from directly accessing authentication tokens. [Heading 2]
- The module also supports Google OAuth authentication to simplify account creation and login. Users can sign in using their Google account without manually creating credentials. After successful authentication, new users are redirected to the profile completion page where academic details such as branch, year, and role are collected. Existing users are redirected directly to the dashboard. [Heading 2]
- Session persistence is implemented through a current-user API endpoint which restores authentication status whenever the application is reloaded. This allows users to continue using the platform without repeatedly logging in. [Heading 2]

- ABSTRACT
- The rapid growth of digital learning has increased the demand for centralized academic platforms that enable efficient knowledge sharing, collaboration, and student engagement. In many educational institutions, study materials, notes, previous year question papers, and academic discussions are often scattered across multiple messaging groups, cloud drives, and social media platforms. This fragmentation makes it difficult for students to access relevant resources, track useful contributions, and receive timely academic support. To address these challenges, GBPIET Notes has been developed as a comprehensive college community web application that integrates academic resource sharing, collaborative learning, social interaction, and AI-powered study assistance within a single platform.
- GBPIET Notes is a full-stack web application designed specifically for the students, faculty members, and administrators of G.B. Pant Institute of Engineering and Technology. The platform provides a centralized ecosystem where users can upload, manage, search, and download academic resources while simultaneously participating in question-answer discussions, community interactions, and collaborative learning activities. The system also incorporates user profiles, follow mechanisms, contribution tracking, leaderboards, activity monitoring, and content moderation to encourage meaningful participation and maintain platform quality.
- The application is implemented using modern web technologies including React.js and Tailwind CSS for the frontend user interface, Express.js and Node.js for backend services, MongoDB for database management, and Supabase Storage for secure cloud-based file storage. Authentication and authorization are handled through JWT-based session management and Google OAuth integration, ensuring secure and seamless access to the platform. The system follows a responsive design approach, allowing users to access all functionalities effectively across mobile devices, tablets, laptops, and desktop systems.
- A significant feature of the platform is its AI-powered study assistant, developed using the Gemini API. The assistant enables users to interact with study materials through natural language queries and supports analysis of PDFs, typed notes, handwritten notes, images, and text documents. This functionality enhances self-learning by providing instant academic assistance and improving accessibility to educational content. In addition, the platform incorporates a report-based moderation mechanism that allows users to report inappropriate content or behaviour, helping maintain a safe and productive academic environment.
- The system consists of several interconnected modules including user authentication, profile management, academic resources and notes sharing, Q&A discussions, community posts, upvote and reputation systems, follow networks, user directory management, leaderboard and contribution analytics, AI-assisted learning support, and moderation services. These modules work together to create an integrated academic community where students can not only access resources but also actively contribute knowledge and collaborate with peers.
- The primary objective of GBPIET Notes is to reduce dependency on scattered communication channels and unorganized file-sharing methods by providing a structured, searchable, and community-driven academic platform. By combining resource management, social collaboration, and artificial intelligence, the system aims to improve academic productivity, encourage knowledge sharing, and create a sustainable digital learning ecosystem for the college community. The project demonstrates the practical application of modern full-stack development technologies in solving real-world educational challenges and provides a scalable foundation for future enhancements such as advanced recommendation systems, notification services, administrative dashboards, and intelligent content retrieval mechanisms.

- 1. INTRODUCTION
- 1.1 Project Background
- In most colleges, academic resources are distributed through informal channels such as messaging groups, personal drives, classroom announcements, and scattered file links. Although these methods are convenient for quick sharing, they often become difficult to manage over time. Students repeatedly ask for the same notes, question papers, assignments, and tutorials because the resources are not indexed, searchable, or linked to a contributor identity.
- GBPIET Notes was designed as a solution to this problem. The platform provides a centralized academic community where notes, questions, answers, posts, profiles, and contribution data are connected together. Instead of treating notes as isolated files, the system treats academic material as a community resource that can be uploaded, liked, discussed, reported, and discovered.
- The project also recognizes that modern students need more than file storage. They need a structured environment where they can ask doubts, receive answers, follow active contributors, see trending material, and get AI-based assistance for study content. For this reason, the platform includes Q&A, community posts, leaderboard analytics, and an AI chatbot in addition to the notes module.
- The application is built as a full-stack web system. The frontend is created using React, Vite, Tailwind CSS, React Router, Axios, and Lucide icons. The backend is created with Node.js, Express.js, MongoDB, Mongoose, JWT authentication, Multer, Supabase Storage, and integration with Google OAuth and Gemini API.
- 1.2 Problem Statement
- Educational institutions continuously generate large volumes of academic content including lecture notes, assignments, laboratory manuals, tutorials, project resources, previous year question papers, and discussion materials. Despite the importance of these resources, their distribution is often decentralized and dependent on temporary communication channels such as messaging applications, email chains, and personal cloud storage accounts. As a result, students face significant difficulties in locating relevant study material when required.
- One of the primary challenges is the absence of a centralized repository where academic resources can be stored, categorized, searched, and accessed efficiently. Students frequently spend considerable time searching for files that were previously shared in class groups or personal chats. This leads to duplication of effort and inefficient utilization of educational resources.
- Another challenge is the lack of a structured academic discussion environment. Students regularly encounter doubts related to course content, assignments, programming problems, and examination preparation. Existing communication channels are not designed for long-term knowledge retention, causing valuable discussions and solutions to disappear within large volumes of messages. Consequently, the same questions are repeatedly asked and answered.
- The absence of contributor recognition also creates a limitation. Students who actively share notes, answer doubts, and assist their peers often receive little acknowledgement for their efforts. Without proper incentives, participation in academic communities tends to decline over time.
- Content moderation presents another significant concern. Open platforms encourage collaboration but can also allow inappropriate or irrelevant content to be shared. Therefore, a balance must be maintained between freedom of contribution and accountability.
- Additionally, modern students increasingly require intelligent assistance while studying. Traditional search mechanisms often fail to provide quick explanations for concepts contained in PDFs, handwritten notes, images, and other learning materials. The growing adoption of artificial intelligence in education highlights the need for integrated AI-powered study support systems.
- Therefore, there is a need for a unified platform that combines academic resource sharing, collaborative discussions, contributor recognition, content moderation, and AI-assisted learning within a single secure and scalable environment. GBPIET Notes aims to address these challenges through a community-driven academic platform specifically designed for college students and faculty members.

During semester studies, students regularly exchange notes, assignments, and examination materials through messaging groups and personal contacts. While these methods appear convenient initially, they become increasingly inefficient as the volume of shared content grows.

New students face additional difficulties because they have limited access to previously shared resources and often depend on senior students for academic guidance.
- Another motivating factor was the absence of a unified platform that combines resource sharing with collaborative learning. Existing solutions generally focus on either file sharing or discussion forums, but rarely integrate both functionalities within a single environment. As a result, academic content and academic discussions remain disconnected.
- The increasing adoption of Artificial Intelligence in education also served as a major source of inspiration. Students increasingly seek immediate explanations, summaries, and conceptual assistance while studying. Integrating AI capabilities directly into the platform allows learners to receive academic support without relying on multiple external tools.
- Furthermore, the project aims to encourage a culture of knowledge sharing by recognizing contributors through credits, likes, followers, activity statistics, and leaderboard rankings. Such recognition helps create a sustainable academic ecosystem where users are motivated to contribute high-quality resources and assist their peers.
- Ultimately, the project was motivated by the vision of creating a centralized digital academic community that improves accessibility, collaboration, engagement, and learning outcomes for students and faculty members.

- 2. LITERATURE REVIEW
- 2.1 Overview
- Academic web applications have evolved from static portals into interactive systems that combine learning resources, communication, analytics, and personalization. A modern academic platform must support structured content, authentication, mobile usability, social interaction, and integration with cloud services.
- GBPIET Notes draws ideas from learning management systems, question-answering communities, social feeds, contribution tracking platforms, and AI assistants. However, it is designed specifically for a college-level peer learning environment rather than for a general public audience.
- With the increasing adoption of digital learning methods, students expect platforms that provide both academic content and interactive engagement. Modern educational systems are moving beyond simple content delivery and focusing on collaborative learning experiences. This shift has influenced the design of GBPIET Notes, where learning resources, community participation, and intelligent assistance are integrated into a single platform. The application aims to bridge the gap between traditional resource repositories and modern social learning environments.
- 2.2 Academic Resource Platforms
- Traditional academic resource systems mainly focus on storing documents. They often provide folders, file names, and download links. While this is useful, such systems usually lack social context, contributor information, likes, comments, and student discussions.
- GBPIET Notes extends this idea by connecting resources to users, profiles, credits, likes, comments, and leaderboard data. This makes resource sharing more interactive and gives visibility to students who contribute original content.
- Many educational institutions rely on cloud drives and departmental websites for resource distribution. Although these solutions provide accessibility, they often lack efficient search capabilities and meaningful user engagement. Students are unable to identify active contributors or evaluate the usefulness of shared content. By integrating resource management with user interaction and contribution tracking, GBPIET Notes creates a more collaborative and sustainable academic knowledge repository.
- 2.3 Community Q&A Systems
- Community Q&A systems are useful because they allow problems and answers to remain visible beyond a single conversation. Platforms such as Stack Overflow demonstrate the importance of searchable questions, answers, votes, and user reputation.
- The Q&A module in GBPIET Notes adapts these ideas for an academic environment. Questions include titles, descriptions, tags, and optional images. Answers can also include images, which is useful for mathematical derivations, circuit diagrams, handwritten explanations, and screenshots.
- A structured Q&A system improves knowledge retention by preserving discussions that would otherwise disappear in chat-based communication channels. Students can search previously answered questions and benefit from solutions provided by their peers. The inclusion of tags and image support further improves content organization and makes the platform suitable for technical, scientific, and engineering subjects where visual explanations are often necessary.
- 2.4 Social Community Features
- Modern web applications often use social interaction patterns such as following users, liking posts, commenting, and viewing profiles. These features help users discover active contributors and stay engaged with the platform.
- The community module in this project includes a feed-style layout, user suggestions, post composer, image carousel, comments, likes, and profile navigation. This helps the platform feel like an academic social network rather than only a file repository.
- Social features also encourage continuous participation and content creation. When users receive likes, followers, and recognition for their contributions, they become more motivated to share valuable resources and assist others. The combination of academic content and social engagement creates a collaborative environment where students can learn from both resources and peer interactions.
- 2.5 AI Study Assistants
- AI assistants can support students by summarizing notes, explaining diagrams, generating important questions, and providing references for further study. Large language models are increasingly used for educational support, but they must be integrated carefully with context and source material.
- The AI chatbot in GBPIET Notes uses Gemini API and a simple vector-style retrieval approach over project content. It is implemented as an independent chat page, supports file uploads, streams responses, and stores local chat history for user convenience.
- Recent advancements in artificial intelligence have made conversational learning tools more accessible and effective. Students can now receive personalized explanations and guidance without waiting for instructor availability. The AI assistant in GBPIET Notes enhances the learning experience by allowing users to interact directly with study materials such as PDFs, images, handwritten notes, and text documents. This functionality improves accessibility and promotes self-directed learning.
- 2.6 Summary
- The literature and platform review shows that an effective academic community application should combine resource sharing, discussion, user identity, moderation, analytics, and AI assistance. GBPIET Notes integrates these areas into one college-focused platform.
- Unlike conventional academic portals that focus only on content distribution, the proposed system combines academic collaboration, social interaction, contribution recognition, and intelligent assistance within a unified environment. The concepts studied in this review provide the foundation for the design and implementation of GBPIET Notes and demonstrate the relevance of integrating multiple educational technologies into a single platform.

- 5. SYSTEM ARCHITECTURE
- 5.1 Architecture Overview
- GBPIET Notes follows a client-server architecture. The frontend is responsible for user interface, routing, responsive layouts, form handling, file selection, and API interaction. The backend handles authentication, authorization, validation, database operations, file upload coordination, AI communication, and response formatting.
- Figure 1: High-Level System Architecture
- 5.2 Frontend Architecture
- The frontend is built with React and Vite. React Router manages page navigation, while Axios communicates with the backend API using the configured base URL. Tailwind CSS is used for styling, responsive utilities, spacing, cards, buttons, and layout.
- The frontend is organized into pages, components, context providers, services, utilities, and constants. Shared components such as UserAvatar, FollowButton, ReportUserButton, CardActionMenu, LikedUsersModal, AttachmentCarousel, UploadPolicyWarning, and ConfirmModal reduce duplication and keep the UI consistent.
- 5.3 Backend Architecture
- The backend uses Express.js with modular route files and controller files. Each major feature has a route group and a controller. Mongoose models represent persistent data entities such as User, Note, Question, Answer, Post, Upvote, Follow, and Report.
- Middleware is used for JWT verification, optional authentication, role checks, file upload handling, AI upload handling, and centralized error handling. Utility files support Supabase uploads, email validation, AI vector retrieval, and reputation recalculation.
- 5.4 Database and Storage Architecture
- MongoDB stores structured application data such as users, notes metadata, Q&A records, posts, comments, upvotes, follows, reports, and profile fields. Supabase Storage stores binary files such as PDFs and images. The database stores public file URLs returned by Supabase.
- 5.5 Authentication and Security Architecture
- Figure 2: Authentication and Profile Completion Flow
- Security is implemented through bcrypt password hashing, JWT access and refresh tokens, protected routes, owner checks, role checks where required, upload validation, report warnings, and moderation through report counts.
- The application uses Cross-Origin Resource Sharing with credentials and sets Cross-Origin-Opener-Policy headers to support Google authentication popups.
- 6. SYSTEM DESIGN
- 6.1 Data Model Design
- The data model is designed around users and their contributions. Users can create notes, questions, answers, and posts. They can also like content, follow other users, and report users. This produces a community graph where academic contribution, reputation, and interaction can be measured.
- 6.2 API Design
- The API follows REST-style route grouping. Each module has dedicated endpoints and uses JSON responses wrapped in a consistent ApiResponse structure. Errors are passed through ApiError and centralized error middleware.
- 6.3 UI/UX Design
- The UI uses soft blue and white visual language with rounded white cards, subtle borders, indigo action buttons, and clean typography. The design is inspired by modern SaaS dashboards and community platforms.
- The navigation was converted from a sidebar into a responsive top navbar. On desktop, links are displayed horizontally. On mobile, a hamburger menu opens a slide-out menu. The profile avatar opens a dropdown with profile, settings, about, contact, and logout links.
- Forms include labels and placeholders. Upload forms include a warning that inappropriate uploads may lead to account restrictions after reports. Modals are used for liked-user lists and delete confirmations.
- 6.4 Responsive Design
- Dashboard cards stack on mobile screens.
- Community user suggestions are hidden on mobile and moved to a user page.
- Q&A cards use a single-column layout.
- Profile page switches from two-column layout to stacked mobile layout.
- Leaderboard activity cards shrink and stack according to viewport.
- Header width was fixed to avoid horizontal scrolling on mobile.
- Post, question, answer, and note cards avoid overflow and keep content visible.
- 6.5 Reusable Components
- Reusable components were created for repeated interface patterns. This improves consistency and reduces future maintenance effort.
- 7. IMPLEMENTATION
- 7.1 Authentication Module
- The authentication module is responsible for providing secure access control to the application and ensuring that only authorized users can access protected features. It supports email/password registration, login, Google authentication, profile completion, logout functionality, and current-user session restoration. The module acts as the entry point to the system and is designed to provide both security and user convenience.
- Passwords are never stored in plain text. Instead, they are securely hashed using the bcrypt library before being stored in the database. During login, entered credentials are verified against the stored hashed password. After successful authentication, JWT access and refresh tokens are generated and stored in HTTP-only cookies. This approach improves security by preventing client-side scripts from directly accessing authentication tokens.
- The module also supports Google OAuth authentication to simplify account creation and login. Users can sign in using their Google account without manually creating credentials. After successful authentication, new users are redirected to the profile completion page where academic details such as branch, year, and role are collected. Existing users are redirected directly to the dashboard.
- Session persistence is implemented through a current-user API endpoint which restores authentication status whenever the application is reloaded. This allows users to continue using the platform without repeatedly logging in.
